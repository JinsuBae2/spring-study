# Java·Spring 학습 기록 01 — 업무 객체부터 첫 API까지

- 학습 기간: 2026-10-07 ~ 2026-10-08
- 프로젝트: 팀 업무 관리 API (`taskapi`)
- 작성 방식: 학습 대화와 현재 코드를 바탕으로 정리한 초안. ‘내 말로 정리’는 학습자가 직접 작성한다.

## 1. 목표와 구현한 것

AI의 도움으로 CRUD를 구현해 본 경험을 바탕으로, 직접 구현하고 동작을 설명하며 검증하는 연습을 시작했다.

- `Task`: 제목, 설명, 상태를 갖는 업무 객체
- `TaskStatus`: `TODO`, `IN_PROGRESS`, `DONE`
- 생성자의 제목 검증: null, 빈 문자열, 공백만 있는 문자열 거부
- `start()`, `complete()`: 순서에 따른 상태 변경과 잘못된 전환 거부
- `GET /tasks/sample`: 고정된 업무를 JSON으로 반환
- `POST /tasks`: 요청의 제목·설명으로 업무를 생성해 반환
- `TaskCreateRequest`: 생성 요청 데이터를 전달하는 record DTO

아직 저장 기능은 없다. POST로 생성한 업무를 이후 요청에서 다시 조회할 수 있는 단계는 아니다.

## 2. 첫 단위 테스트

JUnit의 `@Test`는 테스트 메서드를 표시한다. `assertEquals(기대값, 실제값)`는 두 값이 같은지 확인하고, `assertThrows`는 실행한 코드가 지정한 예외를 던지는지 확인한다.

```java
assertThrows(IllegalArgumentException.class,
    () -> new Task("", "설명"));
```

예외를 기대하는 테스트에서는 해당 예외가 실제로 발생해야 통과한다. 아무 예외도 없거나 다른 종류의 예외가 발생하면 실패한다.

`Task`의 규칙만 확인하는 테스트는 스프링 서버 없이 일반 JUnit 테스트로 실행할 수 있다.

## 3. 막힌 부분과 배운 내용

### @NonNull은 제목 검증을 대신하지 않는다

사용한 어노테이션은 `org.jspecify.annotations.NonNull`이다. null을 허용하지 않는다는 정보를 분석 도구 등에 제공하지만, 그 자체로 실행 중 검사 코드를 삽입하지 않는다. 또한 빈 문자열과 공백 문자열은 null과 다르다.

제목 규칙은 생성자에서 직접 검사했다.

```java
if (title == null || title.isBlank()) {
    throw new IllegalArgumentException("제목은 비어 있을 수 없습니다.");
}
```

### || 조건의 순서가 중요하다

`||`는 왼쪽이 true이면 오른쪽을 실행하지 않는다. 따라서 위 코드는 null일 때 `isBlank()`를 호출하지 않는다.

순서를 `title.isBlank() || title == null`로 바꾸면 null 입력에서 `NullPointerException`이 먼저 발생한다. 빈 문자열 입력에서는 두 순서 모두 제목 검증 조건을 만족한다.

### 예외를 던지는 조건은 ‘허용하지 않는 경우’다

처음에는 `start()`에서 현재 상태가 TODO일 때 예외를 던졌다. 이 조건은 정상적인 시작까지 막는다. TODO가 아닌 경우를 거부하도록 조건을 바꿨다. `complete()` 역시 IN_PROGRESS가 아닌 경우를 거부한다.

### new, throw, throws는 역할이 다르다

```java
new IllegalStateException("잘못된 상태");       // 객체 생성만 함
throw new IllegalStateException("잘못된 상태"); // 예외를 던짐
```

예외를 생성만 했을 때는 실행이 계속되어, 중복 시작 테스트에서 ‘예외를 기대했지만 발생하지 않았다’는 실패가 나왔다.

- `throw`: 실제로 예외를 던지고 현재 실행 흐름을 중단한다.
- `throws`: 메서드나 생성자에서 발생할 수 있는 예외를 선언한다.
- `IllegalArgumentException`: 전달한 인수가 잘못된 경우 사용했다.
- `IllegalStateException`: 현재 업무 상태에서 작업할 수 없는 경우 사용했다.
- `IllegalAccessException`: 이번 규칙과 관계없는 checked 예외였다. 선언 때문에 호출하는 테스트에도 처리 의무가 생겼다.

`IllegalArgumentException`과 `IllegalStateException`은 unchecked 예외로, throws 선언이 필수가 아니다. 선언을 생략해도 본문의 throw는 그대로 동작한다.

## 4. HTTP 요청이 코드로 연결되는 과정

```text
GET /tasks/sample
→ DispatcherServlet이 요청을 받아 매핑된 처리 흐름으로 전달
→ TaskController.getSampleTask() 호출
→ Task 반환
→ JSON 변환 후 HTTP 응답
```

- `@RestController`: 반환값을 응답 본문으로 전달하는 컨트롤러
- `@RequestMapping("/tasks")`: 공통 경로
- `@GetMapping("/sample")`: GET 메서드와 경로 연결
- `@PostMapping`: POST 요청 연결
- `@RequestBody`: 요청 JSON을 요청 객체로 변환

현재 Task의 getter를 통해 응답의 제목·설명·상태를 읽어 JSON으로 변환할 수 있다.

## 5. DTO, 도메인 객체, DAO의 구분

| 구분 | 역할 | 이번 프로젝트 |
|---|---|---|
| DTO | 데이터를 전달 | TaskCreateRequest |
| 도메인 객체 | 업무 데이터와 규칙 관리 | Task |
| DAO | 저장소에 접근해 저장·조회 | 아직 없음 |

학습자는 요청 객체를 따로 만든 이유로 record의 불변성과 데이터 전달 역할을 떠올렸다. 데이터 전달 역할이라는 이해는 맞고, DTO를 분리하는 핵심 이유는 외부 입력과 업무 규칙을 분리하는 데 있다.

요청에서는 제목과 설명만 받는다. 초기 상태 TODO는 Task 생성자가 정한다. 요청 DTO를 분리했다고 모든 입력 검증이 자동으로 수행되는 것은 아니다.

record는 데이터 전달 타입을 간결하게 표현하고 필드 재할당을 막는다. 일반 클래스로 DTO를 만들 수도 있다. record 안에 담긴 가변 객체까지 자동으로 불변이 되는 것은 아니다.

## 6. 검증 기록과 남은 범위

| 항목 | 확인한 증거 | 상태 |
|---|---|---|
| 기본 프로젝트 | 기본 Gradle 테스트 BUILD SUCCESSFUL | 이전 실행에서 확인 |
| GET /tasks/sample | 조력자가 HTTP 200과 지정된 JSON 직접 확인 | 확인 완료 |
| POST /tasks | 학습자가 HTTP 200, 요청 제목·설명, TODO 응답 공유 | 공유된 결과로 확인 |
| Task 단위 테스트 | 생성·빈 제목·시작·중복 시작 테스트 4개가 현재 파일에 있음 | 최신 전체 통과 결과는 미확인 |
| null·공백 제목 | 생성자에 검증 로직 있음 | 해당 테스트는 현재 파일에 없음 |
| complete() | 구현함. 학습자 요청으로 유사 테스트 작성 연습 생략 | 테스트 미검증 |

POST 확인에 사용한 요청:

```bash
curl -i -X POST http://localhost:8080/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"POST API 공부","description":"요청 본문 받아보기"}'
```

공유된 응답 본문:

```json
{"title":"POST API 공부","description":"요청 본문 받아보기","status":"TODO"}
```

터미널 끝의 `%`는 줄바꿈이 없는 응답 뒤에서 zsh가 표시할 수 있는 기호이며, API 오류를 뜻하지 않는다.

## 9. 기록 운영 방식

이 대화에서 ‘오늘 공부 끝’이라고 하면, 그때까지의 대화와 코드를 확인해 이 폴더의 기록을 작성하거나 갱신한다. 같은 날짜의 이어지는 학습은 기존 기록에 반영하고, 새로운 학습일은 별도 파일로 남긴다.

- 실행해서 확인한 결과, 학습자가 공유한 결과, 미검증 항목을 구분한다.
- 학습자의 이해나 감정을 대신 지어내지 않는다.
- ‘내 말로 정리’는 학습자가 작성한다.
- 기록을 모아 블로그 초안을 만들 수 있다. 현재 외부 발행이나 예약 자동화는 설정하지 않았다.
